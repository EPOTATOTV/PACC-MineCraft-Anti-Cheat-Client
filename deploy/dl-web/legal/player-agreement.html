玩家协议

最近更新：2026-10-11

一、这份协议管什么

本协议说明 PACC 在玩家端模式与服务端插件模式下分别做什么、检测依据是什么、你授权了哪些数据，以及当你被判定违规时有哪些流程。使用 PACC 相关软件即表示你接受本协议。

二、玩家端模式做什么

玩家端软件运行在你自己的设备上，只做本机检测、留痕与远程查端，不具备任何封禁或踢出能力，也不会为第三方封禁系统预留接口。也就是说，它不会替任何服务器对你执行封禁。

三、检测依据与数据授权

检测数据只来自你设备本机，不接入游戏服务器 API、不读取游戏服务器数据库。在你使用期间，客户端会采集：

  • 运行环境信息：进程与驱动清单、模块加载记录
  • 硬件与系统指纹摘要（用于识别同设备异常重复）
  • 运行时行为快照：输入时序统计、内存与调用完整性检查结果
  • 对抗性环境信号：调试器、DMA 设备、虚拟化 / 沙箱迹象

这些结果经 PACC 独立通道上报至管控后台，用于风险评分与证据留痕。我们不上报你的个人文件内容、聊天记录或浏览器历史，也不录屏。数据用途与保存期限见隐私政策。

四、红屏与查端

当本机检测的综合风险评分达到阈值时，客户端会触发红屏强制警告，并进入待查验状态。管理后台可对高风险账号发起远程查端，采集运行态证据用于人工核验。红屏只是提示与留痕，本身不等于最终判定。

五、申诉

如果你认为判定有误，可通过管控台自助门户提交申诉。涉及赛事判定证据的部分，需先完成申诉流程后再处理数据查询 / 更正请求。我们鼓励先申诉、再结论。

六、服务端插件模式说明

部分服务器会自愿部署 PACC 服务端插件。该插件运行在服务器运营方自己的进程内，可读取本服务器的数据用于检测，并可依据运营方的配置在本服务器内执行告警、踢出或临时封禁，默认仅告警。这类处置只作用于该服务器，PACC 不支持跨服务器封禁，也不对接任何第三方封禁系统。

请注意：玩家端模式与服务端插件模式是两种独立部署形态，是否部署插件由各服务器自行决定，与本协议中玩家端不封禁的承诺并不冲突。

七、公平使用

你同意不通过调试、注入、篡改内存或伪造上报等方式规避检测。此类行为本身即构成违约，并可能被记录为作弊证据。

Player Agreement

Last updated: 2026-10-11

1. Scope

This agreement explains what PACC does in client mode and server-plugin mode, what it detects, which data you authorise, and what happens if you are flagged. Using PACC software means you accept it.

2. What client mode does

The client runs on your own device and performs local detection, evidence logging and remote inspection only. It has no ban or kick capability and does not expose hooks for third-party ban systems. In other words, it will not ban you on behalf of any server.

3. Detection basis and data you authorise

Detection data comes only from your local device; we do not call game-server APIs or read game-server databases. While you use it, the client collects:

  • Runtime environment: process and driver lists, module load records
  • Hardware and system fingerprint digests (to spot abnormal duplication on the same machine)
  • Runtime behaviour snapshots: input timing statistics, memory and call integrity check results
  • Adversarial environment signals: debuggers, DMA devices, virtualisation / sandbox traces

These results are reported over PACC's own channel to the console for risk scoring and evidence logging. We do not report the contents of your personal files, chat history or browser history, and we do not record your screen. Uses and retention are covered by the Privacy Policy.

4. Red screen and inspection

When the local composite risk score reaches the threshold, the client shows a mandatory red screen warning and enters a pending-inspection state. The console may start a remote inspection of a high-risk account to gather runtime evidence for manual review. A red screen is a prompt and a record, not a final determination.

5. Appeals

If you believe a decision is wrong, submit an appeal through the self-service portal. Where the data forms part of a tournament decision, the appeal must be completed before data access or correction requests are handled. We encourage appealing first, concluding second.

6. About server-plugin mode

Some servers voluntarily deploy the PACC server plugin. It runs inside the server operator's own process, may read that server's data for detection, and may — per the operator's configuration — alert, kick or temporarily ban within that server, with an alert-only default. Such actions apply to that server only. PACC does not support cross-server bans, nor integration with third-party ban systems.

Note: client mode and server-plugin mode are two independent deployment forms. Whether a server deploys the plugin is its own decision, and this does not conflict with the client mode's no-ban commitment.

7. Fair use

You agree not to evade detection by debugging, injecting, tampering with memory, or forging reports. Doing so is itself a breach and may be recorded as cheat evidence.
